# FANN repository instructions

Read `brand/README.md`, `brand/decisions.md` and the relevant brand sections before changing content or implementation. Kay is the final product and visual authority.

Preserve the exact promise `Designed for Confidence. Engineered for Comfort.` and tagline `Support in Style.`. Use Bank Gothic for display and Montserrat for body/UI. The order of confidence and comfort is intentional.

X Edition is excluded from the current website and launch. Do not add its products, navigation, imagery, erotic positioning or a coming-soon teaser. Retain its historical exclusion only in decision documentation. The current development catalogue includes Silver, Gold, Platinum, Black and Legacy, with Seasonal Editions reserved for the next asset batch. Warrior is a historical name for Legacy. Do not infer final specifications or commercial readiness from concept renders.

Keep confirmed facts, inherited source context, proposals and open questions distinguishable. `canonical: true` identifies this repository as the governing foundation; it does not approve unresolved products, a website composition, pricing or a launch date.

This repository is public. Never commit credentials, private financial or supplier material, personal information, or proprietary fonts without confirmed distribution rights. Source references are not proof of product performance.

Use the assignments in `docs/skill-routing.md`. Apply the relevant installed skill and read its current instructions. Do not create a new brand strategy during implementation or apply an unrelated application scaffold to a Shopify theme.

Keep brand facts in `brand/`, business-sensitive planning outside this public repository, and website-specific decisions in `brand/website.md`. Preserve source history when reconciling later documents.

After initial repository setup, use a bounded task branch and a pull request for changes. Merge only work authorized by the user and checked against its scope. Do not publish a storefront, connect paid services, or alter DNS without task authorization. Existing authorization persists; do not request it again unnecessarily.

For brand changes, update the semantic context version and decision history, validate the package, and regenerate `brand/context-packet.json`. Visual and functional website verification become required once a website exists.

For Shopify, preserve native merchant editability: JSON templates, reusable blocks/sections, real product/collection fields and resource pickers. Keep draft prices, unverified materials and release dates out of production copy. Website concept selection precedes the theme skeleton. Read commerce/README.md and docs/shopify-structure.md before store changes.
